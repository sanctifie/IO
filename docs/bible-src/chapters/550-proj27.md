## Ce qu'on construit

```ascii
 1. Terraform (poste) ──► EC2 Jenkins (Jenkins, Docker, SonarQube, Trivy, Terraform, kubectl, AWS CLI)
 2. Job Jenkins « eks-terraform » (apply/destroy) ──► cluster EKS
 3. Job Jenkins « reddit » :
      checkout → npm install → SonarQube → Quality Gate → OWASP DC → Trivy fs
      → docker build + push Docker Hub (tag = BUILD_NUMBER) → Trivy image
      → sed : K8s/deployment.yml → image reddit:<BUILD_NUMBER>  → git commit + push
 4. Argo CD (dans EKS) voit le commit ──► synchronise ──► Deployment reddit
                                                   └── Ingress ──► ALB ──► navigateur
 5. kube-prometheus-stack (Helm) ──► Grafana : CPU, mémoire, réseau des pods, état des nœuds
```

L'application est un clone de **Reddit** écrit en **Next.js**.

## Étape 1 — Le serveur Jenkins avec Terraform

```bash
git clone https://github.com/uniquesreedhar/Reddit-Project.git && cd Reddit-Project
ls Jenkins-server-TF EKS-TF Jenkins-Pipeline-Code K8s
```

:::info Le dossier `Jenkins-server-TF` est vide
Dans la version actuelle du dépôt, `Jenkins-server-TF/` ne contient qu'un fichier texte. Utilise le Terraform du serveur Jenkins du **projet 19** (`jenkins_server/tf-aws-ec2`, avec les corrections d'AMI et de rôle IAM), et le script d'installation `Installation-script.sh` du dépôt Reddit en user data (relis-le : il installe Jenkins, Docker, SonarQube en conteneur, Trivy, Terraform, kubectl, AWS CLI).
:::

Après `terraform apply` : `http://<IP>:8080` (mot de passe initial dans `/var/lib/jenkins/secrets/initialAdminPassword`), crée ton utilisateur, installe les plugins (*Eclipse Temurin installer*, *SonarQube Scanner*, *NodeJS*, *OWASP Dependency-Check*, *Docker* et *Docker Pipeline*, *Pipeline: AWS Steps*, *Pipeline: Stage View*), puis SonarQube sur `http://<IP>:9000`.

**Outils** : `jdk` (17), `nodejs` (16 ou 20), `sonar-scanner`, `DP-Check`, `docker`. **Credentials** : `sonar-token`, `docker` (Docker Hub), `github` (token avec écriture sur ton fork), `nvd-api-key`. Avec un **rôle IAM** sur l'instance, le credential `aws-key` (access keys) du tutoriel est inutile.

## Étape 2 — Le cluster EKS par un pipeline

Fork `Reddit-Project`. Dans `EKS-TF/` : adapte `backend.tf` (ton bucket, ta région), `variables.tfvars` (région, nom du cluster, type d'instance `t3.medium`), et vérifie que l'identité qui crée le cluster en devient administratrice (projet 12, `access_config`).

Job **`eks-terraform`** : *Pipeline from SCM* → ton fork → `Jenkins-Pipeline-Code/Jenkinsfile-EKS-Terraform`. Il est paramétré (`File-Name`, `Terraform-Action`) comme au projet 28 ; remplace l'URL Git par ton fork, supprime ou adapte `withAWS(credentials: 'aws-key', region: 'us-east-1')`, et **ajoute un `input` de validation** avant l'apply/destroy.

```bash
# sur le serveur Jenkins, une fois le cluster créé
aws eks update-kubeconfig --name <cluster> --region eu-west-3
kubectl get nodes
```

## Étape 3 — Le pipeline applicatif

Job **`reddit`** : *Script Path* `Jenkins-Pipeline-Code/Jenkinsfile-Reddit`. Après les étapes de scan (identiques au projet 09), la fin du pipeline doit **construire, pousser, scanner, puis mettre à jour le manifest** :

```groovy
environment {
    SCANNER_HOME = tool 'sonar-scanner'
    IMAGE        = '<toi-dockerhub>/reddit'
    GIT_REPO     = 'github.com/<toi>/Reddit-Project.git'
}
// ...
stage('Build & push Docker') {
    steps {
        script {
            withDockerRegistry(credentialsId: 'docker', toolName: 'docker') {
                sh 'docker build -t $IMAGE:$BUILD_NUMBER . && docker push $IMAGE:$BUILD_NUMBER'
            }
        }
    }
}
stage('Trivy image') {
    steps { sh 'trivy image $IMAGE:$BUILD_NUMBER > trivyimage.txt' }
}
stage('Mise à jour du manifest GitOps') {
    steps {
        withCredentials([string(credentialsId: 'github', variable: 'GITHUB_TOKEN')]) {
            sh '''
              git config user.email "jenkins@exemple.com"
              git config user.name  "Jenkins"
              sed -i -E "s#image: .*/reddit:.*#image: ${IMAGE}:${BUILD_NUMBER}#" K8s/deployment.yml
              git add K8s/deployment.yml
              git commit -m "ci: reddit:${BUILD_NUMBER}"
              git push https://${GITHUB_TOKEN}@${GIT_REPO} HEAD:main
            '''
        }
    }
}
```

:::warn Le pipeline modifie le dépôt qui le déclenche
Comme au projet 18 : si ce job est déclenché par webhook sur **tout** le dépôt, le commit du manifest relance le pipeline indéfiniment. Exclus le dossier `K8s/` du déclenchement (*Polling ignores commits in certain paths*), ou sépare les manifests dans un **second dépôt** (méthode du projet 16, plus propre).
:::

Vérifie que `K8s/deployment.yml` référence bien `<toi-dockerhub>/reddit:…` au départ (sinon le `sed` ne trouvera rien).

## Étape 4 — Argo CD

```bash
kubectl create namespace argocd
kubectl apply -n argocd -f https://raw.githubusercontent.com/argoproj/argo-cd/stable/manifests/install.yaml
# (le tutoriel épingle la v2.4.7, très ancienne : "stable" pointe vers la dernière version stable)
kubectl -n argocd rollout status deploy/argocd-server
kubectl -n argocd patch svc argocd-server -p '{"spec": {"type": "LoadBalancer"}}'    # ou port-forward (gratuit)

export ARGOCD_SERVER=$(kubectl get svc argocd-server -n argocd -o json | jq -r '.status.loadBalancer.ingress[0].hostname')
export ARGO_PWD=$(kubectl -n argocd get secret argocd-initial-admin-secret -o jsonpath="{.data.password}" | base64 -d)
echo "https://$ARGOCD_SERVER  admin / $ARGO_PWD"
```

Crée l'Application (fichier versionné, plutôt que des clics) :

```yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata: { name: reddit, namespace: argocd }
spec:
  project: default
  source:
    repoURL: https://github.com/<toi>/Reddit-Project.git
    targetRevision: main
    path: K8s
  destination: { server: https://kubernetes.default.svc, namespace: default }
  syncPolicy:
    automated: { prune: true, selfHeal: true }
```

**L'Ingress** (`K8s/ingress.yml`) nécessite un contrôleur d'Ingress : installe l'**AWS Load Balancer Controller** (projet 15, étapes 2 à 4) et vérifie `ingressClassName: alb` et les annotations `alb.ingress.kubernetes.io/scheme: internet-facing` et `target-type: ip`. *(Sans contrôleur, l'Ingress reste sans adresse ; à défaut, expose le Service en `LoadBalancer`.)*

:::check
- Argo CD : application `reddit` *Synced* et *Healthy* ; l'arbre des ressources (Deployment → ReplicaSet → Pods, Service, Ingress).
- `kubectl get ingress` → ADDRESS (ALB) → l'application Reddit dans le navigateur.
- Modifie un texte de l'application, push : Jenkins construit `reddit:<n+1>`, commit le manifest, Argo CD déploie. Le numéro de build est visible dans `kubectl describe deploy reddit | grep Image`.
:::

## Étape 5 — Monitoring avec Prometheus et Grafana

```bash
helm repo add prometheus-community https://prometheus-community.github.io/helm-charts && helm repo update
helm install monitoring prometheus-community/kube-prometheus-stack -n monitoring --create-namespace
kubectl -n monitoring get pods
kubectl -n monitoring port-forward svc/monitoring-grafana 3000:80
kubectl -n monitoring get secret monitoring-grafana -o jsonpath="{.data.admin-password}" | base64 -d; echo
```

*(Le tutoriel installe Prometheus et Grafana séparément et expose leurs Services en `LoadBalancer` ; la pile `kube-prometheus-stack` installe tout, déjà relié, avec des dizaines de tableaux de bord Kubernetes. Détails en annexe A.10.)*

## Étape 6 — Analyser et interpréter les métriques

Ouvre Grafana (`http://localhost:3000`) et explore :

| Tableau (dossier *Kubernetes*) | Ce qu'il montre | Question à se poser |
|---|---|---|
| *Compute Resources / Cluster* | CPU et mémoire par namespace | Le cluster est-il trop grand (gaspillage) ou trop petit ? |
| *Compute Resources / Namespace (Pods)* | conso de chaque pod de `default` | Les `requests`/`limits` du Deployment sont-ils réalistes ? |
| *Compute Resources / Pod* | un pod précis, avec ses limites | Le pod frôle-t-il sa limite mémoire (risque d'OOMKilled) ? |
| *Networking / Pod* | trafic réseau entrant/sortant | Le trafic suit-il la charge attendue ? |
| *Node Exporter / Nodes* | santé des nœuds (CPU, disque, réseau) | Un nœud sature-t-il ? |

:::exo Provoquer et observer
1. Génère de la charge : `kubectl run load --rm -it --image=busybox -- sh -c "while true; do wget -q -O- http://<service-reddit>; done"`.
2. Observe la montée du CPU dans *Compute Resources / Pod*.
3. Ajoute un **HPA** (`kubectl autoscale deployment reddit --cpu-percent=50 --min=2 --max=6`) et regarde le nombre de pods augmenter, puis redescendre après la charge.
4. Note dans ton `NOTES.md` les valeurs observées et ce que tu en conclus sur le dimensionnement.
:::

## Dépannage

:::fix
- **Argo CD *OutOfSync* permanent** : un champ modifié dans le cluster par un autre acteur (par exemple `replicas` par le HPA). Solution : retirer `replicas` du manifest quand un HPA gère la taille, ou configurer `ignoreDifferences` dans l'Application.
- **Ingress sans ADDRESS** : contrôleur ALB absent ou mal configuré (projet 15, dépannage).
- **Le `sed` ne modifie rien** : l'image du manifest ne correspond pas au motif `…/reddit:…`.
- **Pods en `Pending`** : nœuds trop petits pour l'application + Argo CD + la pile de monitoring : passe à 3 nœuds ou à `t3.large`.
:::

## Nettoyage

:::clean
1. Supprime l'Application Argo CD (cascade), `helm uninstall monitoring -n monitoring`, les Services LoadBalancer d'Argo CD/Grafana s'il y en a, l'Ingress, puis le contrôleur ALB.
2. Job `eks-terraform` avec `destroy`.
3. `terraform destroy` du serveur Jenkins.
4. Vérifie load balancers, volumes EBS (Prometheus en crée parfois), NAT Gateways.
:::
