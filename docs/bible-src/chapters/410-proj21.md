# Projet 21 — Pipeline CI/CD avec les outils DevOps d'AWS

:::card
| | |
|---|---|
| Niveau | ★★★☆☆ Intermédiaire |
| Durée | 4 à 6 heures |
| Coût | quelques centimes (CodeBuild à la minute, CodePipeline 1 pipeline gratuit/mois en V1 ou ~0,002 $/minute d'action en V2, une `t3.micro`) |
| Compétences | CodeConnections (GitHub), CodeBuild + `buildspec.yml`, Parameter Store pour les secrets, Docker Hub, artefacts S3, agent et application CodeDeploy, `appspec.yml` et hooks, CodePipeline |
| Prérequis | Leçon 13, projet 04 (Docker) |
| Dépôt d'origine | `DevOps-Project-21` : application Netflix-clone (React/Vite), `Dockerfile`, `buildspec.yaml`, `appspec.yml`, `scripts/start.sh`, `scripts/stop.sh` |
:::

## Ce qu'on construit

```ascii
 GitHub ──(CodeConnections)──► CodePipeline
                                 ├─ Source  : récupère le code
                                 ├─ Build   : CodeBuild (buildspec.yaml)
                                 │             docker build (clé TMDB lue dans Parameter Store)
                                 │             docker push ──► Docker Hub  <toi>/netflix-react-app:latest
                                 │             artefact (appspec.yml + scripts/) ──► S3
                                 └─ Deploy  : CodeDeploy ──► EC2 (agent CodeDeploy + Docker)
                                               ApplicationStop : scripts/stop.sh  (arrête l'ancien conteneur)
                                               AfterInstall    : scripts/start.sh (docker run -p 8080:80)
                                                                   ──► http://<IP>:8080
```

:::info CodeCommit n'est plus disponible
Le dépôt d'origine utilise **CodeCommit** (avec une clé SSH d'utilisateur IAM). AWS a **fermé CodeCommit aux nouveaux clients** en juillet 2024. On utilise donc **GitHub** relié à AWS par **CodeConnections**. Le reste du pipeline est identique, et c'est d'ailleurs la configuration la plus courante en entreprise.
:::

## Étape 1 — Le code

1. Crée un dépôt GitHub `netflix-aws-cicd` et copies-y le contenu de `DevOps-Project-21`.
2. Ouvre `scripts/start.sh` et `scripts/stop.sh` : ils contiennent l'image `dhruvdarji123/netflix-react-app` (l'auteur). Remplace par **`<toi-dockerhub>/netflix-react-app`**. Fais de même dans `buildspec.yaml`.
3. Crée une **clé d'API TMDB** (compte gratuit sur `themoviedb.org` → *Settings → API*). L'application l'utilise pour afficher les films.

Rends les scripts plus robustes (le `stop.sh` d'origine échoue au tout premier déploiement, quand aucun conteneur n'existe) :

```bash
#!/bin/bash
# scripts/stop.sh
docker rm -f netflix 2>/dev/null || true
docker image rm <toi-dockerhub>/netflix-react-app:latest 2>/dev/null || true
```

```bash
#!/bin/bash
# scripts/start.sh
docker pull <toi-dockerhub>/netflix-react-app:latest
docker run -d --name netflix --restart unless-stopped -p 8080:80 <toi-dockerhub>/netflix-react-app:latest
```

## Étape 2 — Les secrets dans Parameter Store

*Systems Manager → Parameter Store → Create parameter* (ou en CLI) :

```bash
aws ssm put-parameter --name /myapp/docker-credentials/username --type String       --value "<toi-dockerhub>"
aws ssm put-parameter --name /myapp/docker-credentials/password --type SecureString --value "<token-dockerhub>"
aws ssm put-parameter --name /myapp/api/key                     --type SecureString --value "<cle-tmdb>"
```

Le `buildspec.yaml` les lit dans sa section `env.parameter-store` : CodeBuild les injecte comme variables d'environnement, masquées dans les logs.

## Étape 3 — Le projet CodeBuild

1. *Developer Tools → Settings → Connections → Create connection* → **GitHub** → autorise l'application AWS sur ton compte, limitée au dépôt `netflix-aws-cicd` → la connexion doit être *Available*.
2. *CodeBuild → Create build project* :
   - nom `netflix-build` ; *Source* : **GitHub** via la connexion, dépôt `netflix-aws-cicd` ;
   - *Environment* : image managée **Amazon Linux**, runtime *Standard*, dernière image ; **coche « Privileged »** (*Enable this flag if you want to build Docker images*) ;
   - *Service role* : *New service role* (`codebuild-netflix-build-service-role`) ;
   - *Buildspec* : *Use a buildspec file*, nom **`buildspec.yaml`** (l'extension `.yaml` n'est pas celle par défaut, `.yml` : précise-la !) ;
   - *Artifacts* : **Amazon S3**, bucket `io-21-artifacts-<prenom>` (à créer), *packaging* **Zip**.
3. **Donne au rôle CodeBuild le droit de lire les paramètres** : IAM → le rôle → *Add permissions* → politique inline autorisant `ssm:GetParameters` sur `arn:aws:ssm:eu-west-3:<compte>:parameter/myapp/*` (et `kms:Decrypt` si clé KMS personnalisée).

:::why Le mode « Privileged »
CodeBuild exécute ton build dans un conteneur. Construire une image Docker **depuis** un conteneur nécessite des privilèges supplémentaires (démarrer un démon Docker interne). Sans ce drapeau, `docker build` échoue avec `Cannot connect to the Docker daemon`.
:::

:::warn `runtime-versions: nodejs: latest`
Le `buildspec.yaml` d'origine demande `nodejs: latest`. Certaines images CodeBuild refusent `latest` ; mets une version explicite supportée (par exemple `nodejs: 20`). La construction de l'application se fait de toute façon **dans** le Dockerfile (étape `node:…-alpine`).
:::

Lance un premier build manuel (*Start build*) : il doit pousser l'image sur Docker Hub et déposer le zip d'artefacts dans S3.

## Étape 4 — L'instance de déploiement

1. **Rôle IAM** pour l'instance : `AmazonEC2RoleforAWSCodeDeploy` (lecture des artefacts S3) + `AmazonSSMManagedInstanceCore`. Nom `io-21-ec2-role`.
2. **Instance** : Ubuntu 24.04, `t3.micro`, rôle `io-21-ec2-role`, SG : 22 depuis ton IP, **8080 depuis ton IP**. **Tag** `Name=netflix-codedeploy` (CodeDeploy trouvera l'instance par ce tag).
3. **Installer Docker et l'agent CodeDeploy** (user data ou SSH) :

```bash
sudo apt update && sudo apt install -y docker.io ruby-full wget
sudo systemctl enable --now docker
cd /tmp
wget https://aws-codedeploy-eu-west-3.s3.eu-west-3.amazonaws.com/latest/install    # adapter la région (2 fois)
chmod +x install && sudo ./install auto
sudo systemctl status codedeploy-agent
```

:::tip Le fichier `install` du dépôt d'origine
Le dossier contient un fichier `install` vide (0 octet) : c'est un reste du script d'installation de l'agent. Télécharge la version officielle comme ci-dessus, depuis le bucket de **ta** région.
:::

## Étape 5 — L'application CodeDeploy

1. **Rôle de service CodeDeploy** : IAM → *Create role* → *AWS service* → **CodeDeploy** → cas d'usage *CodeDeploy* (politique `AWSCodeDeployRole`) → `io-21-codedeploy-role`.
2. *CodeDeploy → Applications → Create application* → nom `netflix-app`, plateforme **EC2/On-premises**.
3. *Create deployment group* → `netflix-dg`, rôle `io-21-codedeploy-role`, type *In-place*, *Environment configuration* : **Amazon EC2 instances** → tag `Name` = `netflix-codedeploy` ; *Install AWS CodeDeploy Agent* : *Never* (déjà installé) ; *Load balancer* : décoché.

## Étape 6 — Le pipeline

*CodePipeline → Create pipeline* → *Build custom pipeline* :

- nom `netflix-pipeline`, type V2, *New service role* ;
- **Source** : GitHub (via la connexion), dépôt, branche `main`, déclenchement sur push ;
- **Build** : AWS CodeBuild, projet `netflix-build` ;
- **Deploy** : AWS CodeDeploy, application `netflix-app`, groupe `netflix-dg`.

À la création, le pipeline s'exécute une première fois.

:::why Le chemin des artefacts entre les étapes
CodePipeline stocke la sortie de chaque étape dans son **bucket d'artefacts** S3. L'étape Build reçoit le code source, produit un artefact (ici tout le dépôt, qui contient `appspec.yml` et `scripts/`), que l'étape Deploy remet à CodeDeploy. L'agent sur l'instance télécharge ce zip, lit **`appspec.yml` à la racine**, et exécute les hooks. Si `appspec.yml` n'est pas à la racine de l'artefact, le déploiement échoue.
:::

:::check
- Les trois étapes du pipeline sont vertes.
- *CodeBuild → Build history* : logs du build, image poussée sur Docker Hub.
- *CodeDeploy → Deployments* : détail des événements de cycle de vie (`ApplicationStop`, `AfterInstall`…) avec leur durée.
- `http://<IP_PUBLIQUE_EC2>:8080` affiche le clone de Netflix avec des affiches de films.
- Modifie un texte dans `src/`, push sur GitHub : le pipeline repart seul et la page change.
:::

## Dépannage

:::fix
- **CodeBuild : `AccessDeniedException` sur `ssm:GetParameters`** : la politique inline de l'étape 3.
- **CodeBuild : `YAML_FILE_ERROR` / buildspec introuvable** : nom du fichier (`buildspec.yaml` vs `.yml`).
- **CodeBuild : `Cannot connect to the Docker daemon`** : mode *Privileged* non coché.
- **CodeBuild : `toomanyrequests` de Docker Hub** : limite de téléchargements anonymes atteinte ; le `docker login` avant le build (déplace-le en `pre_build`) ou une image de base depuis `public.ecr.aws` règle le problème.
- **CodeDeploy : déploiement bloqué en *In progress* puis échec « agent not responding »** : l'agent ne tourne pas, ou l'instance n'a pas de rôle permettant d'accéder à S3 (`/var/log/aws/codedeploy-agent/codedeploy-agent.log`).
- **CodeDeploy : `ScriptFailed` sur ApplicationStop** au premier déploiement : le `stop.sh` d'origine échoue car le conteneur n'existe pas encore (d'où notre version avec `|| true`).
- **Page blanche ou sans films** : la clé TMDB n'a pas été passée au build (`--build-arg TMDB_V3_API_KEY=$KEY`).
:::
