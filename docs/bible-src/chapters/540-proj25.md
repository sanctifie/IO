## Ce qu'on construit

**JPetStore** est l'application Java de démonstration historique (une animalerie en ligne, basée sur MyBatis et Spring). Le pipeline construit et analyse le code, puis **délègue à Ansible** la construction de l'image et le déploiement sur Kubernetes.

```ascii
 Terraform ──► EC2 Jenkins (t3.large)           Terraform ──► EC2 k8s-master + k8s-worker
                │                                               (kubeadm, annexe A.6)
                │ pipeline Jenkins                                     ▲
                │  clean → checkout → mvn compile → mvn test            │
                │  → SonarQube → Quality Gate → mvn install (war)       │
                │  → OWASP Dependency-Check                             │
                │  → ansiblePlaybook docker.yaml  (sur localhost : build, tag, push, run :8081)
                │  → ansiblePlaybook kube.yaml    ──SSH──► master : copie deployment.yaml, kubectl apply
                ▼
          http://<IP-jenkins>:8081/jpetstore          http://<IP-worker>:<NodePort>/jpetstore
```

:::why Pourquoi passer par Ansible ?
Ansible apporte ici une couche de **configuration et d'orchestration** réutilisable : les mêmes playbooks peuvent déployer sur un serveur ou sur dix, et ils sont exécutables hors de Jenkins (depuis ton poste, par exemple). C'est aussi l'occasion de voir l'intégration **Jenkins → Ansible**, fréquente dans les entreprises qui ont beaucoup de serveurs « classiques ». Dans un environnement 100 % Kubernetes, on lui préférerait Helm ou Argo CD.
:::

## Étape 1 — Les instances avec Terraform

Le tutoriel fournit un petit code Terraform qui crée une instance Ubuntu `t2.large` et un Security Group ouvert à tout. Écris le tien en t'inspirant du `main.tf` du **projet 06** (AMI Ubuntu par recherche dynamique, SG restreint), avec trois instances : `jenkins` (`t3.large`, 30 Go), `k8s-master` et `k8s-worker` (`t3.medium`).

:::warn « Allow all inbound and outbound traffic »
Le Security Group du tutoriel autorise **tout le trafic entrant depuis Internet**. Ouvre seulement : 22 (ton IP), 8080 Jenkins, 9000 SonarQube, 8081 application (ton IP), tout le trafic **entre** les trois instances (règle avec le SG lui-même comme source), et la plage NodePort 30000-32767 depuis ton IP sur le worker.
:::

## Étape 3 — Ansible sur le serveur Jenkins

```bash
sudo apt install -y software-properties-common
sudo add-apt-repository --yes --update ppa:ansible/ansible
sudo apt install -y ansible
ansible --version
ansible-galaxy collection install community.docker     # module docker_login utilisé par docker.yaml
```

Jenkins : plugin **Ansible** → *Tools → Ansible installations* : nom **`ansible`**, chemin `/usr/bin`.

**L'inventaire** `/etc/ansible/hosts` :

```ini
[local]
localhost ansible_connection=local

[k8s]
k8s-master ansible_host=<IP_PRIVEE_MASTER> ansible_user=ubuntu
```

**La clé SSH** pour joindre le master : Jenkins → *Credentials* → *SSH Username with private key*, ID **`ssh`**, user `ubuntu`, clé privée `io-key.pem` (celle des instances). Le plugin la fournira à Ansible.

## Étape 5 — Adapter les playbooks

Fork `jpetstore-6` et ouvre `Ansible/docker.yaml` :

```yaml
- name: docker build and push
  hosts: local
  become: yes
  tasks:
    - name: Build Docker Image
      command: docker build -t petstore .
      args:
        chdir: /var/lib/jenkins/workspace/petstore      # le workspace du job : le job doit s'appeler "petstore"
    - name: tag image
      command: docker tag petstore:latest harshitgupta21/petstore:latest
    - name: Log in to Docker Hub
      community.docker.docker_login:
        registry_url: https://index.docker.io/v1/
        username: harshitgupta21
        password: <password>                            # ← mot de passe EN CLAIR dans le dépôt !
    - name: Push image
      command: docker push harshitgupta21/petstore:latest
    - name: Run container
      command: docker run -d --name pet1 -p 8081:8080 harshitgupta21/petstore:latest
```

**À corriger :**

1. Le pseudo Docker Hub → le tien.
2. **Le mot de passe en clair** : passe-le en variable. Dans le pipeline, `ansiblePlaybook` accepte `extraVars` ; on y injecte un credential Jenkins (étape 6). Dans le playbook : `password: "{{ docker_password }}"` et `username: "{{ docker_user }}"`. *(Encore mieux : **Ansible Vault** pour chiffrer les variables sensibles dans le dépôt.)*
3. **Le `docker run`** échoue au deuxième passage (conteneur `pet1` existant). Ajoute avant une tâche `command: docker rm -f pet1` avec `ignore_errors: true`, ou utilise le module `community.docker.docker_container` avec `state: started` et `recreate: true` (idempotent).
4. Le `chdir` dépend du **nom du job** : nomme ton job `petstore`, ou utilise `{{ workspace }}` passé en `extraVars` avec la valeur `${env.WORKSPACE}`.

`Ansible/kube.yaml` supprime l'ancien déploiement, copie `deployment.yaml` sur le master puis l'applique. Remplace l'image dans `deployment.yaml` par la tienne, et préfère `kubectl apply` seul (le `delete` provoque une coupure à chaque déploiement ; `apply` + changement de tag fait un rolling update sans interruption).

:::info Le Dockerfile de JPetStore
```dockerfile
FROM openjdk:17.0.2
COPY . /usr/src/myapp
WORKDIR /usr/src/myapp
RUN ./mvnw clean package
CMD ./mvnw cargo:run -P tomcat90
```
L'image recompile tout le projet et lance Tomcat via le plugin Maven **Cargo** : simple mais lourd (JDK complet, sources, dépôt Maven dans l'image). L'image `openjdk` est en outre **dépréciée**. Exercice : réécris-le en multi-stage, avec `maven:3.9-eclipse-temurin-17` pour builder et `tomcat:9.0-jre17` pour exécuter (`COPY --from=build /app/target/jpetstore.war /usr/local/tomcat/webapps/`).
:::

## Étape 6 — Le pipeline

Credential *Username with password* ID **`dockerhub`**. Job **Pipeline** nommé **`petstore`** :

```groovy
pipeline {
    agent any
    tools {
        jdk 'jdk17'
        maven 'maven3'
    }
    environment {
        SCANNER_HOME = tool 'sonar-scanner'
    }
    stages {
        stage('Clean workspace') { steps { cleanWs() } }
        stage('Checkout') {
            steps { git branch: 'master', url: 'https://github.com/<toi>/jpetstore-6.git' }
        }
        stage('Compilation') { steps { sh 'mvn -B clean compile' } }
        stage('Tests')       { steps { sh 'mvn -B test' } }
        stage('Analyse SonarQube') {
            steps {
                withSonarQubeEnv('sonar-server') {
                    sh '$SCANNER_HOME/bin/sonar-scanner -Dsonar.projectName=Petstore -Dsonar.projectKey=Petstore -Dsonar.java.binaries=target/classes'
                }
            }
        }
        stage('Quality Gate') {
            steps { script { waitForQualityGate abortPipeline: false, credentialsId: 'Sonar-token' } }
        }
        stage('Build du war') { steps { sh 'mvn -B clean install -DskipTests=true' } }
        stage('OWASP Dependency-Check') {
            steps {
                withCredentials([string(credentialsId: 'nvd-api-key', variable: 'NVD_KEY')]) {
                    dependencyCheck additionalArguments: "--scan ./ --format XML --nvdApiKey ${NVD_KEY}", odcInstallation: 'DP-Check'
                }
                dependencyCheckPublisher pattern: '**/dependency-check-report.xml'
            }
        }
        stage('Docker via Ansible') {
            steps {
                withCredentials([usernamePassword(credentialsId: 'dockerhub', usernameVariable: 'DH_USER', passwordVariable: 'DH_PASS')]) {
                    dir('Ansible') {
                        ansiblePlaybook credentialsId: 'ssh', disableHostKeyChecking: true, installation: 'ansible',
                            inventory: '/etc/ansible/hosts', playbook: 'docker.yaml',
                            extraVars: [docker_user: env.DH_USER, docker_password: [value: env.DH_PASS, hidden: true]]
                    }
                }
            }
        }
        stage('Kubernetes via Ansible') {
            steps {
                dir('Ansible') {
                    ansiblePlaybook credentialsId: 'ssh', disableHostKeyChecking: true, installation: 'ansible',
                        inventory: '/etc/ansible/hosts', playbook: 'kube.yaml'
                }
            }
        }
    }
}
```

:::why `sonar.java.binaries`
Le scanner Sonar a besoin des fichiers **compilés** pour analyser du Java. Le tutoriel met `-Dsonar.java.binaries=.` (tout le dossier) : ça fonctionne, mais `target/classes` est plus précis et plus rapide.
:::

## Dépannage

:::fix
- **`ERROR! couldn't resolve module/action 'community.docker.docker_login'`** : la collection n'est pas installée **pour l'utilisateur jenkins** (`sudo -u jenkins ansible-galaxy collection install community.docker`).
- **`Permission denied (publickey)` vers le master** : credential `ssh` incorrect, ou mauvais `ansible_user`.
- **`kubectl: connection refused` dans `kube.yaml`** : sur le master, le kubeconfig n'est configuré que pour root, ou la tâche s'exécute avec `become`. Lance `kubectl` en tant qu'`ubuntu`.
- **`docker build` : chdir introuvable** : le job ne s'appelle pas `petstore`.
- **La page JPetStore renvoie 404** : l'URL inclut le contexte `/jpetstore`.
:::

:::clean
*Terminate* les trois instances (ou `terraform destroy`), révoque le token Docker Hub si besoin.
:::
