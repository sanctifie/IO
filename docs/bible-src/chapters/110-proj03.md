## Ce qu'on construit

Une instance EC2 Linux sur laquelle tu vas jouer le rôle d'administrateur système : créer des utilisateurs et des groupes, construire une arborescence de dossiers, gérer finement qui possède quoi, manipuler des fichiers sous différentes identités, puis ajouter un disque supplémentaire et le monter.

C'est un projet sans architecture compliquée, mais **toutes** les commandes que tu vas taper reviendront dans les 29 projets suivants.

## L'arborescence à construire

Le dépôt d'origine montre l'arborescence sous forme d'image. La voici, reconstituée à partir des consignes :

```ascii
/
├── dir1/
│   └── f1
├── dir2/
│   └── dir1/
│       └── dir2/
│           └── dir10/
├── dir4/
├── dir6/
├── dir7/
│   └── dir10/
├── dir8/
├── f2
└── opt/
    └── dir14/
        └── dir10/
```

:::warn On travaille directement sous `/`
Créer des dossiers à la racine n'est **pas** une bonne pratique sur un vrai serveur ; ici, c'est un exercice sur une machine jetable. Tu la détruiras à la fin.
:::

## Étape 0 — Lancer l'instance

Suis la procédure « Lancer une instance » de la leçon 3 : Ubuntu 24.04, `t3.micro`, key pair `io-key`, SSH autorisé depuis **My IP**, tag `Project=io-03`. **Note l'AZ** de l'instance (onglet *Networking*, par exemple `eu-west-3a`) : tu en auras besoin à l'étape 7.

```bash
ssh -i ~/.ssh/io-key.pem ubuntu@<IP_PUBLIQUE>
sudo apt update && sudo apt upgrade -y
sudo hostnamectl set-hostname labo-linux     # un nom lisible dans l'invite
exec bash                                    # recharger le shell pour voir le nouveau nom
```

## Étape 1 — En tant que super-utilisateur

Passe root pour toute cette étape :

```bash
sudo -i
```

**1.1 — Créer user1, user2, user3 avec un mot de passe.**

```bash
for u in user1 user2 user3; do
  useradd -m -s /bin/bash "$u"     # -m : crée /home/$u ; -s : shell bash
  passwd "$u"                      # tape un mot de passe deux fois
done
```

:::why Pourquoi `-m -s /bin/bash` ?
Sans `-m`, l'utilisateur n'a pas de dossier personnel. Sans `-s /bin/bash`, il hérite de `/bin/sh`, un shell minimal sans complétion ni historique. Sur Ubuntu, la commande `adduser` (avec un *d* en plus) fait tout ça de façon interactive ; `useradd` est la commande bas niveau, la même sur toutes les distributions, donc celle qu'on utilise dans les scripts.
:::

**1.2 — Créer les groupes devops et aws.**

```bash
groupadd devops
groupadd aws
```

**1.3 — Faire de devops le groupe principal de user2 et user3.**

```bash
usermod -g devops user2
usermod -g devops user3
```

**1.4 — Ajouter aws comme groupe secondaire de user1.**

```bash
usermod -aG aws user1
id user1 user2 user3     # vérification
```

```text
uid=1001(user1) gid=1001(user1) groups=1001(user1),1005(aws)
uid=1002(user2) gid=1004(devops) groups=1004(devops)
uid=1003(user3) gid=1004(devops) groups=1004(devops)
```

`gid` est le groupe principal ; `groups` liste tous les groupes. Le groupe principal est celui qui est attribué aux fichiers que l'utilisateur crée.

**1.5 — Créer l'arborescence.**

```bash
mkdir -p /dir1 /dir2/dir1/dir2/dir10 /dir4 /dir6 /dir7/dir10 /dir8 /opt/dir14/dir10
touch /dir1/f1 /f2
tree -L 4 /dir1 /dir2 /dir7 /opt/dir14      # (sudo apt install tree si absent)
```

`-p` crée les dossiers parents manquants et ne râle pas si le dossier existe déjà.

**1.6 et 1.7 — Donner /dir1, /dir7/dir10 et /f2 au groupe devops et à l'utilisateur user1.**

```bash
chown user1:devops /dir1 /dir7/dir10 /f2
ls -ld /dir1 /dir7/dir10 /f2
```

```text
drwxr-xr-x 2 user1 devops 4096 ... /dir1
drwxr-xr-x 2 user1 devops 4096 ... /dir7/dir10
-rw-r--r-- 1 user1 devops    0 ... /f2
```

`ls -ld` affiche les informations **du dossier lui-même** (sans `-d`, `ls` afficherait son contenu).

## Étape 2 — En tant que user1

**Le problème** : créer des utilisateurs et des groupes demande les droits root. Un utilisateur normal ne peut pas le faire. Pour que l'exercice soit faisable, on donne à user1 le droit d'utiliser `sudo` :

```bash
usermod -aG sudo user1        # (toujours en root) ; sur Amazon Linux le groupe s'appelle wheel
exit                          # quitter root, on redevient ubuntu
sudo su - user1               # devenir user1 (le - charge son environnement)
```

:::exo Observe d'abord l'échec
Avant d'ajouter user1 au groupe `sudo`, essaie `useradd user4` en tant que user1. Tu obtiens `useradd: Permission denied`. **Lire et comprendre ce message est le vrai but de l'exercice** : c'est le système de droits qui fonctionne.
:::

```bash
whoami                         # user1
sudo useradd -m -s /bin/bash user4 && sudo passwd user4
sudo useradd -m -s /bin/bash user5 && sudo passwd user5
sudo groupadd app
sudo groupadd database
exit
```

## Étape 3 — En tant que user4

user4 doit écrire dans `/dir6`, `/`, `/dir1` et `/dir2/...`, qui appartiennent à root (sauf `/dir1`, à user1). Il n'a aucun droit d'écriture dedans. Deux possibilités :

- **Option pédagogique** : essaie sans droits, constate les `Permission denied`, puis donne `sudo` à user4 (`sudo usermod -aG sudo user4` depuis ubuntu) et préfixe les commandes par `sudo`.
- **Option « propre »** : donner l'accès en écriture via un groupe. Par exemple, rendre `/dir6` accessible en écriture au groupe devops et y ajouter user4. C'est ainsi qu'on fait en entreprise : **jamais de sudo pour tout le monde**.

On prend l'option pédagogique pour avancer :

```bash
sudo usermod -aG sudo user4    # en tant que ubuntu
sudo su - user4
sudo mkdir /dir6/dir4                    # 3.1
sudo touch /f3                           # 3.2
sudo mv /dir1/f1 /dir2/dir1/dir2/        # 3.3 : déplacer f1 dans /dir2/dir1/dir2
sudo mv /f2 /f4                          # 3.4 : renommer = déplacer vers un nouveau nom
ls /dir2/dir1/dir2/ /                    # vérification
exit
```

:::why `mv` sert à la fois à déplacer et à renommer
Pour Linux, renommer un fichier, c'est le « déplacer » vers un autre nom dans le même dossier. Il n'existe pas de commande `rename` dédiée dans les outils de base.
:::

## Étape 4 — En tant que user1

```bash
sudo su - user1

# 4.1 — Créer /home/user2/dir1 (le dossier d'un AUTRE utilisateur : il faut sudo)
sudo mkdir /home/user2/dir1

# 4.2 — Aller dans /dir2/dir1/dir2/dir10 et créer /opt/dir14/dir10/f1 en chemin RELATIF
cd /dir2/dir1/dir2/dir10
sudo touch ../../../../opt/dir14/dir10/f1
ls -l /opt/dir14/dir10/
```

:::why Compter les `..`
Depuis `/dir2/dir1/dir2/dir10`, chaque `..` remonte d'un niveau : `dir10` → `dir2` → `dir1` → `dir2` → `/`. Il faut donc **4** `..` pour arriver à la racine, puis on redescend dans `opt/dir14/dir10`. Astuce pour vérifier : `realpath ../../../../opt/dir14/dir10` affiche le chemin absolu correspondant.
:::

```bash
# 4.3 — Déplacer ce fichier dans le dossier personnel de user1
sudo mv /opt/dir14/dir10/f1 ~/
sudo chown user1: ~/f1           # il appartenait à root (créé avec sudo) : on le récupère

# 4.4 — Supprimer /dir4 récursivement
sudo rm -r /dir4

# 4.5 — Vider /opt/dir14 (supprimer tout ce qu'il contient, mais garder le dossier) en une commande
sudo rm -rf /opt/dir14/*
ls -la /opt/dir14

# 4.6 — Écrire le texte dans /f3
echo "Linux assessment for an DevOps Engineer!! Learn with Fun!!" | sudo tee /f3
cat /f3
exit
```

:::warn Pourquoi `sudo echo "..." > /f3` ne marche pas
Dans `sudo echo texte > /f3`, c'est **ton shell** (non root) qui ouvre `/f3` pour la redirection `>`, avant même que `sudo` s'exécute. Résultat : `Permission denied`. La solution standard est `echo texte | sudo tee /f3` : c'est `tee`, lancé en root, qui écrit le fichier (`tee -a` pour ajouter à la fin). Tu reverras ce piège souvent.
:::

:::info `rm -rf /opt/dir14/*` et les fichiers cachés
L'étoile `*` ne correspond **pas** aux fichiers cachés (ceux qui commencent par un point). Pour tout supprimer, y compris les fichiers cachés : `sudo find /opt/dir14 -mindepth 1 -delete`.
:::

## Étape 5 — En tant que user2

```bash
sudo usermod -aG sudo user2      # en tant que ubuntu
sudo su - user2

sudo touch /dir1/f2              # 5.1
sudo rm -r /dir6                 # 5.2 (contient dir4 : il faut -r)
sudo rm -r /dir8                 # 5.3

# 5.4 — Remplacer "DevOps" par "devops" dans /f3 sans éditeur
sudo sed -i 's/DevOps/devops/g' /f3
cat /f3
```

:::why Décortiquer `sed -i 's/DevOps/devops/g' /f3`
- `sed` (*stream editor*) transforme du texte ligne par ligne.
- `-i` modifie le fichier **sur place** (*in-place*). Sans `-i`, le résultat est seulement affiché.
- `s/ancien/nouveau/` : substitution.
- `g` : toutes les occurrences de la ligne, pas seulement la première.

C'est l'outil roi pour modifier un fichier de configuration dans un script (tu l'utiliseras dans des pipelines pour changer un tag d'image dans un manifest Kubernetes, projet 18).
:::

**5.5 — Avec vi, copier la ligne 1 et la coller 10 fois.**

```bash
sudo vim /f3
```

Dans vim : place-toi sur la ligne 1 (`gg`), tape `yy` (copier la ligne), puis `10p` (coller 10 fois), puis `:wq` et Entrée.

**5.6 — Remplacer « Engineer » par « engineer » en une seule commande.** Deux méthodes :

```bash
sudo sed -i 's/Engineer/engineer/g' /f3
# ou dans vim :  :%s/Engineer/engineer/g
grep -c engineer /f3     # doit afficher 11 (le nombre de lignes qui contiennent "engineer")
```

**5.7 — Supprimer /f3.**

```bash
sudo rm /f3
exit
```

## Étape 6 — En tant que root

```bash
sudo -i

# 6.1 — Trouver tous les fichiers nommés f3 et afficher leurs chemins absolus
find / -name "f3" 2>/dev/null
# (Il ne devrait plus rien y avoir, puisqu'on a supprimé /f3. Crée-en un pour tester : touch /tmp/f3)

# 6.2 — Compter le nombre de fichiers dans /
ls -A / | wc -l                          # tous les éléments (dossiers compris)
find / -maxdepth 1 -type f | wc -l       # seulement les fichiers ordinaires

# 6.3 — Afficher la dernière ligne de /etc/passwd
tail -n 1 /etc/passwd
```

```text
user5:x:1007:1007::/home/user5:/bin/bash
```

Chaque ligne de `/etc/passwd` contient, séparés par `:` : nom, `x` (le mot de passe est dans `/etc/shadow`), UID, GID principal, commentaire, dossier personnel, shell.

## Étape 7 — Créer et attacher un volume EBS de 5 Go

Dans la console AWS :

1. **EC2 → Elastic Block Store → Volumes → Create volume**.
2. *Volume type* : `gp3` ; *Size* : `5` GiB.
3. *Availability Zone* : **la même que ton instance** (celle notée à l'étape 0).
4. Tag `Name=io-03-data`, `Project=io-03` → **Create volume**.
5. Sélectionne le volume → **Actions → Attach volume** → choisis ton instance → *Device name* : `/dev/sdf` → **Attach**.

:::why Pourquoi la même AZ ?
Un volume EBS est un disque **réseau** hébergé dans une AZ précise. Il ne peut être attaché qu'à une instance de la **même** AZ. Pour le déplacer, on fait un *snapshot* (copie stockée dans S3, valable pour toute la région) puis on recrée un volume dans l'autre AZ.
:::

En ligne de commande, l'équivalent est :

```bash
aws ec2 create-volume --size 5 --volume-type gp3 --availability-zone eu-west-3a \
  --tag-specifications 'ResourceType=volume,Tags=[{Key=Project,Value=io-03}]'
aws ec2 attach-volume --volume-id vol-xxxxxxxx --instance-id i-xxxxxxxx --device /dev/sdf
```

## Étape 8 — Créer le système de fichiers et monter le disque

```bash
sudo -i
lsblk
```

```text
NAME         MAJ:MIN RM  SIZE RO TYPE MOUNTPOINTS
nvme0n1      259:0    0    8G  0 disk
└─nvme0n1p1  259:1    0    7G  0 part /
nvme1n1      259:2    0    5G  0 disk          ← notre nouveau disque, vide
```

:::info `/dev/sdf` est devenu `/dev/nvme1n1`
Sur les instances récentes (familles t3, m5 et suivantes, dites « Nitro »), les volumes EBS apparaissent comme des disques NVMe. Le nom choisi dans la console (`/dev/sdf`) n'est qu'une étiquette. Repère le bon disque grâce à sa **taille** (5G) et à l'absence de point de montage.
:::

```bash
# 8.1 — Créer un système de fichiers ext4 sur le disque
file -s /dev/nvme1n1            # "data" = vide, rien à perdre. S'il affiche un système de fichiers, STOP.
mkfs.ext4 /dev/nvme1n1

# 8.2 — Monter le disque sur /data
mkdir -p /data
mount /dev/nvme1n1 /data

# 8.3 — Vérifier
df -h /data
```

```text
Filesystem      Size  Used Avail Use% Mounted on
/dev/nvme1n1    4.9G   24K  4.6G   1% /data
```

:::danger `mkfs` efface tout
`mkfs` détruit toutes les données du disque ciblé. Vérifie trois fois le nom du périphérique. Formater `/dev/nvme0n1` (le disque système) rendrait l'instance inutilisable.
:::

**Bonus indispensable : rendre le montage permanent.** Après un redémarrage, `/data` ne sera plus monté. Il faut l'ajouter à `/etc/fstab` :

```bash
blkid /dev/nvme1n1                         # récupère l'UUID du système de fichiers
echo "UUID=<ton-uuid>  /data  ext4  defaults,nofail  0  2" >> /etc/fstab
umount /data && mount -a                   # teste fstab : aucune erreur = c'est bon
df -h /data
```

On utilise l'**UUID** plutôt que `/dev/nvme1n1` parce que les noms NVMe peuvent changer d'un démarrage à l'autre. L'option `nofail` évite que l'instance refuse de démarrer si le disque est absent.

:::check Vérification finale
- `id user1` montre le groupe `aws` ; `id user2` montre `devops` comme groupe principal.
- `ls -ld /dir1 /dir7/dir10` montre `user1 devops`.
- `/dir4`, `/dir6`, `/dir8`, `/f3` n'existent plus ; `/f4` et `/dir1/f2` existent.
- `ls ~user1/` contient `f1`.
- `df -h` affiche `/data` ; après `sudo reboot` et reconnexion, `/data` est toujours monté.
:::

## Dépannage

:::fix
- **`Permission denied (publickey)`** au SSH : mauvais utilisateur (`ubuntu` pour Ubuntu, `ec2-user` pour Amazon Linux), mauvaise clé, ou clé pas en `chmod 400`.
- **SSH qui tourne dans le vide puis `Connection timed out`** : le Security Group n'autorise pas ton IP (elle a peut-être changé : ta box en change parfois). Mets à jour la règle avec *My IP*.
- **`user1 is not in the sudoers file`** : user1 n'est pas dans le groupe `sudo`, ou il ne s'est pas reconnecté depuis l'ajout (les groupes sont lus à la connexion : `exit` puis `sudo su - user1`).
- **Le volume n'apparaît pas dans la liste d'attachement** : il n'est pas dans la même AZ que l'instance.
- **L'instance ne redémarre plus après une modification de fstab** : erreur dans la ligne ajoutée. Utilise la *EC2 Serial Console* ou détache le disque racine et corrige-le depuis une autre instance. D'où l'importance de tester avec `mount -a` et d'utiliser `nofail`.
:::

## Nettoyage

:::clean
1. **Terminate** l'instance (EC2 → Instances → Instance state → Terminate).
2. **Supprime le volume de 5 Go** : il n'est **pas** supprimé avec l'instance, car il a été créé séparément (EC2 → Volumes → état *available* → Delete).
3. Vérifie qu'aucun volume ni Elastic IP ne traîne.
4. Garde la key pair `io-key` (gratuite) pour les projets suivants.
:::

:::interview
- Quelle différence entre groupe principal et groupe secondaire ? *Le principal est attribué aux fichiers créés par l'utilisateur ; les secondaires donnent des droits supplémentaires.*
- Que signifie `chmod 640` ? *Propriétaire : lecture/écriture ; groupe : lecture ; autres : rien.*
- Comment ajouter un disque à une instance Linux et le rendre persistant ? *Créer et attacher le volume (même AZ), `mkfs`, `mount`, puis une entrée dans `/etc/fstab` avec l'UUID et `nofail`.*
- Pourquoi `sudo echo x > /fichier` échoue-t-il ? *La redirection est faite par le shell non privilégié ; utiliser `tee`.*
:::
